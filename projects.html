AWS EKS Platform

Three-Tier Microservices on Amazon EKS

83% Faster Deploys Zero Downtime

The Challenge

Deploying a distributed three-tier application (React frontend, Node.js backend, RDS PostgreSQL) across dev, staging, and production environments suffered from configuration drift, manual rollout errors, and deployment durations exceeding 30 minutes.

Architectural Solution

Designed a fully automated GitOps delivery pipeline on AWS EKS. Modular Terraform provisions the VPC, multi-AZ subnets, NAT gateways, EKS cluster, and IAM OIDC roles. Jenkins executes build, lint, and security scan stages before pushing Docker images to Amazon ECR. ArgoCD detects repository changes and triggers self-healing rolling updates on Kubernetes.

// Terraform EKS Module Definition
module "eks" {
  source          = "terraform-aws-modules/eks/aws"
  version         = "19.15.3"
  cluster_name    = "prod-eks-cluster"
  cluster_version = "1.28"
  vpc_id          = module.vpc.vpc_id
  subnet_ids      = module.vpc.private_subnets

  eks_managed_node_groups = {
    general = {
      min_size     = 2
      max_size     = 10
      desired_size = 3
      instance_types = ["m5.large"]
      capacity_type  = "ON_DEMAND"
    }
  }
}

GitOps Delivery

Continuous GitOps Deployment via ArgoCD

Zero Drift Auditable Git

The Challenge

Direct `kubectl` invocations and manual manifest edits created severe configuration drift between Kubernetes cluster states and repository declarations, leaving no auditable history or reliable rollback pathway.

Architectural Solution

Established Git as the single source of truth using ArgoCD. Implemented Helm charts with values hierarchy for multiple environments. Configured automated sync policies with self-healing and pruning enabled to revert uncommitted manual cluster adjustments instantly.

// ArgoCD Application Custom Resource
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: prod-three-tier
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://github.com/Rajesh-210/k8s-manifests
    targetRevision: HEAD
    path: environments/prod
  destination:
    server: https://kubernetes.default.svc
    namespace: production
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
Observability

End-to-End Prometheus & Grafana Monitoring

−70% MTTR 100% Metrics

The Challenge

Blind spots in cluster resource saturation, unmonitored pod crash loops, and slow triage times caused incident response cycles to drag out over several hours without proactive alerting.

Architectural Solution

Deployed the kube-prometheus-stack Helm chart with custom PrometheusRules for crash detection, CPU throttling, and node memory pressure. Connected Alertmanager to Slack webhooks for immediate on-call notifications, paired with Grafana dashboards for deep telemetry.
